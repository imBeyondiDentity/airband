# Changelog — Airband

Хронология всех доработок и фиксов с момента первой сборки. Разбито по темам,
внутри каждой — по порядку.

---

## Дизайн и вёрстка

### Единый визуальный язык с Music DNA
Первая версия браузерного интерфейса была собрана на собственной палитре
(сине-янтарной), не связанной с остальными инструментами. По скриншотам
iDentity Prompt Engine пипеткой сняты точные значения: фон `#0F1313`,
акцент `#FF7F44`, состояния выбора `#9F3E16`/`#2E211D`/`#FFC4A3`, кремовый
текст `#E8E6E3`. Шрифты — Playfair Display для заголовка, JetBrains Mono
для служебной обвязки (лейблы, кнопки, теглайны), Inter для тела текста.
Стало: браузерная версия неотличима по стилю от остальных инструментов
семейства, вместо отдельного дизайна.

### Два реальных бага, найденных при проверке рендером
- `[hidden]`-атрибут перебивался собственными `display: grid/flex` в CSS —
  блоки результата и плеера могли показываться раньше, чем появлялись
  данные. Почему стало лучше: добавлено `[hidden] { display: none !important }`
  — атрибут теперь побеждает всегда, а не иногда.
- `−11.0 LUFS` переносилось на две строки из-за более широкого
  моноширинного шрифта. Стало: колонка значения расширена, значения
  держатся в одну строку.

### Однофайловая сборка вместо трёх
Изначально браузерная версия была тремя файлами (`index.html` + `app.css` +
`app.js`). При открытии не через настоящий веб-сервер (например,
предпросмотр внутри чата) относительные ссылки не резолвились, и стили
не подтягивались — снаружи это выглядело как «всё сломано», хотя код был
рабочий. Стало: CSS и JS зашиты прямо в HTML, каждый файл самодостаточен и
работает вообще без исключений — что при предпросмотре, что на реальном
хостинге.

### Пресеты переименованы
«Спасение MP3» и «Только воздух» звучали как случайный набор слов. Стало:
«Восстановление MP3» (парно с «Полировка WAV» — разная степень агрессии,
разные слова) и «Только верх» (то же слово, что уже используется в подписи
слайдера строчкой ниже, а не изолированное «воздух»).

### Сетка пресетов вместо «лестницы»
Плашки пресетов были на flex с шириной по содержимому — «Восстановление
MP3» и «Только верх» получались заметно разного размера. Стало: сетка
2×2 с равными ячейками, текст центрирован; на узких экранах переносится
цельным блоком, а не вразнобой.

### Панель треков больше не оставляет пустоту
При пустом списке треков панель «Треки» была короче панели «Обработка»
(`align-items: start` в гриде колонок не давал им растянуться на равную
высоту) — справа от короткой панели зияла голая чернота на всю высоту
длинной. Стало: панели растягиваются на равную высоту, а пустое
состояние («Пока пусто» + кнопки) центрируется в освободившемся
пространстве, вместо того чтобы прилипать к верху над пустотой. Как
только появляется трек — центрирование само уходит, список ведёт себя
как обычно.

### Кнопки «до/после» — равная ширина и одинаково заметная подсветка
Две проблемы:
- Кнопки были разной ширины (размер по содержимому текста — «после»
  шире, чем «до»). Причина — `flex: 1` внутри `inline-flex`-контейнера
  без заданной ширины ничего не выравнивает, делить контейнеру нечего.
  Стало: фиксированная ширина под более длинное слово каждого языка.
- Выбранное состояние «до» подсвечивалось едва заметной серой полоской,
  а «после» — ярко-оранжевой. Стало: подсветка «до» сделана такой же
  явной (белая полоса вместо тускло-серой), просто другим цветом.

### Легенда спектра больше не сталкивается с подписью среза
Оба элемента — HTML-легенда «до/после» и подпись частоты среза,
рисуемая на канвасе — тянулись в правый верхний угол. Поскольку Suno
почти всегда режет в районе 15–20 кГц (правая часть логарифмической
шкалы), столкновение было не случайностью на одном файле, а
гарантированным поведением почти для любого трека. Стало: легенда
перенесена в левый нижний угол, где на канвасе вообще ничего не
рисуется — коллизия исключена в принципе, а не подправлена точечно.

### Мелкие правки текста
- Эйброу-лейбл: «Suno Audio Engine» → «Audio Restoration Engine» во всех
  трёх файлах (роутер + обе языковые версии).
- Убрана секция «Что тут происходит» из обеих языковых версий.
- Футер («Всё считается в браузере…») принудительно держится в две
  строки на любом экране от 360px и шире — раньше на узких телефонах
  получалось три строки. Дополнительно переформулирована первая фраза:
  «Всё считается» → «Весь процесс».

### Консистентность с Music DNA — в обе стороны
После того как Airband был приведён к дизайну Music DNA, обнаружилось
обратное расхождение: у `index.html` самой Music DNA заголовок был
фиксированного размера (44px) и двойной отступ до карточек (margin на
h1 и отдельный margin-top на блоке ссылок). Стало: перенесены точные
параметры из Airband — `clamp(44px, 12vw, 64px)` для заголовка, единый
источник отступа. Проверено сравнением координат блока на одинаковой
ширине экрана: было 11px расхождения по вертикали, стало 2px (десктоп),
и то, что осталось на мобильной ширине — чисто из-за разной длины
текста ссылок, не из-за вёрстки.

## Локализация

### Английская версия и роутер выбора языка
Собрана полная английская версия (`en.html`) — не калька перевода, а
переформулированные тексты, включая строки, которые генерирует сам JS
(статусы обработки, единицы измерения кГц→kHz, дБ→dB и так далее).
Добавлен `index.html`-роутер по образцу iDentity Prompt Engine — эйброу,
серифный заголовок, две карточки-ссылки, футер с точкой. Все три файла
самодостаточны; переход по ссылке между ними резолвится только когда
все три лежат рядом на настоящем хостинге (это ограничение способа
предпросмотра, а не самих файлов).

### README на двух языках
`README.md` (русский) и `README.en.md` (британский английский,
`colour`/`optimise`-конвенции) — держатся синхронно при каждой правке
интерфейса, а не пишутся один раз и забываются.

## Python-версия

Собрана с нуля как отдельный инструмент для пакетной обработки и более
высокого качества, а не урезанная копия браузерной:

- **Слежение за огибающей** — уровень нового верха выводится из наклона
  спектра под срезом и меняется вместе с музыкой, а не лежит ровным
  слоем.
- **Фильтры с линейной фазой** (FIR) вместо биквадов — верх не
  размазывается по времени.
- **Честная передискретизация** — насыщение считается на 4× частоте
  через полифазные фильтры, алиасинг не долетает до слышимой полосы.
- **Подгонка под референс-трек** — сглаженное отношение спектров,
  ограниченное шестью децибелами, применяется фильтром с линейной фазой.
- **Альбомный режим** — один общий сдвиг громкости на весь альбом вместо
  выравнивания каждого трека по отдельности (которое убивает динамику
  между тихими и громкими треками).
- **Итеративная нормализация** — лимитер сам снижает громкость, поэтому
  один проход недостаточно точен; уточняется до попадания в пределах
  0.1 дБ.
- **Самопроверка DSP** (`selftest.py`) — калибровка измерителя громкости
  по эталону стандарта, проверка лимитера, детектора среза, качества
  восстановления. Запускается после любых правок.

## Обзор мастеринг-инструментов и что из него внедрено

По запросу собран обзор open-source мастеринг-утилит с GitHub (без
торрентов и пиратских копий закрытого софта — их всё равно нельзя
адаптировать под задачу, там нет доступа к DSP-коду). Из обзора в проект
внедрены две конкретные вещи:

### Master Assistant (авто-параметры)
Идея — из плагина [oXygen](https://github.com/Wamphyre/oXygen): он
слушает вход и сам пишет настройки вместо того, чтобы предлагать
человеку угадывать пресет. Реализовано с нуля, в обеих версиях
(`--preset auto` в Python, кнопка «Авто» в браузере):

- крутизна обрыва → насколько агрессивно достраивать верх (жёсткий
  MP3-срез сильнее, мягкий WAV-скат бережнее, полный диапазон без
  обрыва — досинтез выключается совсем);
- реальный измеренный избыток на 250–400 Гц против середины (600–2500
  Гц) → чистить муть только там, где она правда есть, а не всегда
  фиксированные −2.5 дБ вслепую;
- существующая стерео-ширина трека (RMS side/mid) → уже широкому треку
  досыпается меньше, почти моно — больше.

Проверено на трёх синтетических случаях (жёсткий MP3, средний
WAV-подобный, полностью плавный без обрыва) — калибровка честно
различает их разными числами, не выдаёт одно и то же. Добавлен
отдельный блок в `selftest.py`.

### Лимитер с hold-стадией
Сверено с лимитером Hyrax из [Matchering](https://github.com/sergree/matchering).
У них после пика гейн держится внизу ещё некоторое время, прежде чем
начать отпускать — без этого на транзиентных материалах (барабаны,
перкуссия) лимитер «дышит» слишком быстро. У прежней реализации была
только lookahead-стадия без hold, и единственной страховкой от
перехлёста был грубый `clip()` постфактум. Добавлено в обе версии
(Python и браузер):

- hold-плато ~40 мс после каждого пика;
- математическая гарантия того, что сглаженный гейн никогда не
  превышает реально необходимый в моменте — раньше на этот случай
  был только клип, теперь перехлёст исключён по конструкции.

При реализации в Python найден и исправлен реальный баг в собственном
коде: параметр `origin` у `scipy.ndimage.minimum_filter1d` даёт
систематический сдвиг результата на больших окнах (1920 сэмплов) —
проверено численно на эталонном сигнале, найдена верная формула через
принудительно нечётное окно. В JS та же логика проверена отдельным
Node-скриптом до вставки в браузерный файл — там сработала с первого
раза. На тесте с одиночным транзиентом: hold теперь держится ровно
~40мс как задумано (было — вообще не проверялось), жёсткий clip
почти никогда не требуется (0–10 сэмплов на 288000, было — не
измерялось вовсе).

## Лицензия и оформление репозитория

### MIT-лицензия
Добавлен файл `LICENSE` в корень — разрешено всё, включая коммерческое
использование, единственное условие — сохранить копирайт в копиях.
Отдельно проговорено в README: hold-стадия лимитера сверена по идее с
Hyrax из Matchering (сам он под GPLv3), но код не копировался, только
концепция — авторским правом не защищена, так что MIT-лицензия Airband
ничем не нарушается.

### Иконка (favicon)
По образцу другого инструмента (Duo) — SVG прямо в `<link rel="icon">`
как data-URI, без отдельного файла картинки. Растущие полосы
эквалайзера на тёмном фоне: три приглушённо-серые, последняя —
акцентно-оранжевая, отсылка к самой идее инструмента («та самая
восстановленная полоса, которой не хватало»). Добавлена во все три
файла (роутер + обе языковые версии), проверена рендером на 128px и на
реальном размере фавикона 16px — читается на обоих.

## Что в сумме изменилось

| Было | Стало |
|---|---|
| Своя палитра, не связанная с остальными инструментами | Точное соответствие Music DNA — цвета, шрифты, структура |
| Один язык (русский) | RU + EN + роутер выбора языка |
| Три файла, ломались при предпросмотре | Один самодостаточный файл на каждую версию |
| Фиксированные пресеты с числами «на глаз» | Авто-режим считает параметры из самого трека |
| Лимитер без hold, страховка — только постфактум-clip | Hold-стадия ~40мс, перехлёст исключён по конструкции |
| Только браузерная версия | + Python CLI для батч-обработки и более высокого качества |
| Не было самопроверки DSP | `selftest.py` — громкость, лимитер, детектор среза, авто-параметры |
| Не было лицензии | MIT, файл `LICENSE` в корне |
| Дефолтная вкладка браузера без иконки | SVG-фавикон во всех трёх файлах |
